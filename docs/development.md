# 本地开发与验收

## 启动

```sh
cd motro
npm ci
npm run dev
```

默认 `HOST=0.0.0.0`、`PORT=3030`，监听所有本机网卡，以便同局域网手机访问。只在电脑上调试时，可以运行 `HOST=127.0.0.1 npm run dev`，但此时手机无法连接。

macOS 如弹出网络访问或防火墙提示，需允许 Node.js 接受局域网连接。本项目不自动更改系统防火墙。

检查服务：

```sh
curl http://localhost:3030/api/health
# {"ok":true,"name":"motro","version":"0.1.2"}
curl http://localhost:3030/api/version
```

## 修改代码后的操作

| 修改位置 | 操作 |
| --- | --- |
| `apps/mobile` | 刷新手机网页，静态资源不缓存 |
| `apps/server` | `npm run dev` 自动重启；内存会话清空，需重新配对 |
| `apps/extension` | 到扩展管理页点击重新加载，再重新配对；必要时刷新被控制网页 |

插件调试：`chrome://extensions` → Motro → service worker 检查视图。手机端可用电脑浏览器打开同一网页调试表单；真正的双指手感需要手机验证。

插件固定默认地址位于 `apps/extension/background.js` 的 `DEFAULT_SERVER`，弹窗不提供地址输入。仅调试时可在后台控制台用 `chrome.storage.local.set({ serverUrl: 'http://localhost:4040' })` 临时覆盖；恢复默认执行 `chrome.storage.local.remove('serverUrl')`，结束后重新启动连接。

每次交付先执行一次 `npm run version:bump`，统一更新根包、三个 workspace、扩展 manifest 与 lockfile。`npm run check` 验证版本一致。不要逐文件、逐次修改都重复递增。

访问计数默认写入 `data/visits.json`，测试使用独立临时目录。不要提交、删除或重置实际运行数据。部署将 `DATA_DIR` 设置到代码目录外。

## 自动测试

```sh
npm run verify
npx playwright install chromium  # 仅首次需要网络下载
npm run test:e2e
```

服务端集成测试启动随机本机端口，不依赖开发服务。浏览器测试独占 `127.0.0.1:4031`，使用临时浏览器配置文件并自动删除，不碰日常 Chrome 个人数据。

浏览器端到端测试加载真实扩展，模拟移动设备指针与双指触摸，验证：居中连接码、复制地址、二维码携码、手动输入 / 扫码自动申请、电脑拒绝 / 确认、关闭弹窗并闲置 35 秒后持续控制、页面滚动与轻量惯性、触摸停止惯性、原生缩放、重置、刷新重连、访问序号和主动断开。截图写入忽略提交的 `test-results/`。

如果测试浏览器下载较慢，也可以显式使用本机近期版本的 Chrome，通过实验性 CDP 扩展加载接口运行，不使用日常浏览器个人数据：

```sh
MOTRO_CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' npm run test:e2e
```

该可选路径要求浏览器支持 `Extensions.loadUnpacked`；默认仍推荐 Playwright 配套 Chromium，以保持测试可复现。

## 手工验收清单

- [ ] Chrome 加载插件后无错误；Edge 单独验证一次。
- [ ] 手机同一 Wi-Fi 能打开打印的地址，断网但局域网仍连通时也能加载本地页面。
- [ ] 正确连接码进入待确认，电脑批准前不能滚动。
- [ ] 系统相机扫码自动进入待确认，无需再次输入码，仍须电脑批准；刷新码后旧二维码无效。
- [ ] 错误码给出提示，连续错误触发限流，过一分钟恢复。
- [ ] 电脑拒绝后手机可重新申请；过期码不可配对。
- [ ] 单指上滑向下浏览，单指下滑向上浏览，速度可调。
- [ ] 快滑松手续滑，慢拖 / 停顿不续滑，再次触摸立即停止惯性。
- [ ] 双指张开放大、捏合缩小；手机自身页面不随之缩放。
- [ ] 手机整页无上下滚动，触控板占据主要空间；小屏、横屏和键盘弹出后控件不被遮挡。
- [ ] 重置缩放恢复 100%；切换电脑标签页后目标正确。
- [ ] 关闭插件弹窗后保持连接；打开待确认提示能看到请求。
- [ ] 主页面和常见内嵌滚动列表各测试一次；鼠标放到目标列表区域。
- [ ] `chrome://settings` 等受保护页面给手机提示，不导致后台报错退出。
- [ ] 手机刷新恢复连接；Wi-Fi 短时断开后恢复；手机锁屏再解锁。
- [ ] 电脑结束会话后旧手机不能继续控制；手机断开后旧令牌失效。
- [ ] iOS Safari 与 Android Chrome 分别验证触摸、地址栏变化和横竖屏。
- [ ] 页面刷新时 `no.N` 增一；服务重启和代码更新后序号保留。

## 常见故障

**手机打不开网址**：不要输入 `localhost`；检查是否同一 Wi-Fi、访客网络是否启用了设备隔离、是否误选 VPN 网卡、macOS 防火墙是否阻挡 Node.js。

**插件连接失败**：确认服务正在运行；电脑可先打开健康检查地址。固定默认服务为 `http://localhost:3030`，部署后统一修改代码中的默认地址为 HTTPS 域名，不支持 URL 子路径；注意清除调试覆盖值。

**连接了但网页不动**：先切换到普通网站，不要停留在扩展管理页；扩展刚安装时可刷新目标网站；列表页面将电脑鼠标移到需要滚动的区域再试。PDF/iframe 不在首版保证范围。

**手机一直等待确认**：打开电脑工具栏里的 Motro 弹窗并点击「确认授权」。第一版不弹系统通知。

**服务改代码后手机断开**：这是预期行为，开发热重启丢失会话；插件会重新生成码，手机需重新配对。

**浏览器暂停后台或手机锁屏断线**：前台恢复后会尝试重连；超过电脑断线保留时间，需重新配对。不要把自动化测试通过视为休眠场景的真机保证。
