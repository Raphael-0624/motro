# 架构与技术决策

## 产品范围

手机网页是一块输入设备，不投屏、不远程桌面，不控制操作系统。电脑端扩展只控制当前浏览器中的网页滚动和页面缩放。

```text
手机网页 (apps/mobile)
      │ HTTP 获取页面 / WebSocket 发送手势
      ▼
Node.js 服务 (apps/server)
      │ WebSocket 转发，只有已获确认的手机可以发送控制
      ▼
浏览器扩展后台 (apps/extension/background.js)
      ├─ native-wheel.js → debugger → 页面中心原生鼠标滚轮
      └─ chrome.tabs.setZoom → 标签页原生缩放
```

## 为什么仍然有服务端

普通浏览器扩展不能直接作为局域网 TCP/WebSocket 监听服务。四位码解决「匹配谁」，不解决「怎么通信」。本地阶段将通信服务放在开发电脑；远程阶段将同一进程部署到云端，手机和扩展都主动连接云服务。

手机静态网页和 WebSocket 使用同一个域名、端口，不额外引入前端开发服务器、跨域配置、打包器或数据库。当前运行时唯一外部依赖是 `ws`。

二维码使用本地打包的 `qrcode-generator`（MIT）生成，不发往外部服务。二维码 URL 的 fragment 携带四位连接码，手机读取后自动申请配对并从地址栏移除；不会绕过电脑授权。

## 会话生命周期

1. 扩展连接 `/ws`，发送 `host.open`，服务生成独立的 host token 和四位码。
2. 手机发送 `mobile.join`。服务验证未过期、未占用、未配对后通知扩展，并进入待确认状态。
3. 用户在电脑端批准后，服务生成独立的 mobile token，允许该手机发送控制。
4. 手机网页通过 Pointer Events 识别单指位移和双指间距变化，按动画帧合并，最多每帧分别发送一次滚动和缩放。
5. 扩展再次合并指令，串行操作最近聚焦窗口的当前标签页，避免缩放读写竞态。
6. 手机和扩展都发送 20 秒应用心跳。扩展要求 Chrome 116+，使用持续 WebSocket 消息维持 MV3 后台活动，另有 alarm 用于恢复连接。
7. 断线使用令牌重连。电脑断线超过两分钟后清理会话；服务进程重启时所有会话清空。手机断线不会立刻释放配对，避免网络抖动时被其他手机抢占。
8. 用户主动结束会话或手机主动断开，撤销相应令牌。手机主动断开后电脑获得新的连接码。

正常在线会话不设闲置过期，不会因连接码五分钟过期而结束授权。未配对码临近到期由扩展自动刷新。网络断开持续重试，但浏览器休眠可能暂停脚本，不承诺锁屏期间保持实时网络。

## 手势、版本与持久化

单指位移同时支持 `dx` / `dy`。扩展用 `chrome.debugger` 附着当前标签页，只读取视口尺寸，通过 `Input.dispatchMouseEvent` 在视口中心发送 `mouseMoved` / `mouseWheel`，由浏览器和 Canvas 应用自行处理可信滚轮输入，不遍历 DOM、也不调用容器 `scrollBy`。不会移动系统光标。

调试会话串行使用；停止、手机离线、切换标签页或窗口时释放，防止退出后继续输入。外部取消调试会阻止立即重新附着。权限范围较大且有浏览器调试提示，不可隐藏提示；与开发者工具 / 其他调试插件可能冲突。Canvas 处理器已自动测试，实际飞书登录文档仍待手工验收。

0.1.5 将滚轮准备与回执分离：附着、定位和释放保持串行，实际滚轮最多两条在途。达到上限等待一条完成，扩展合并期间收到的增量，避免无限队列；异步输入错误仍反馈给手机。连续手势复用中心和 hover 状态，停顿超过 160ms 后重新读取；窗口调整、页面缩放或导航时主动失效缓存。扩展不再每次处理完后额外等待 16ms。本机压力测试 60 次滚动的调试调用由 180 次降到 62 次，最终位移完整；这不是公网延迟或飞书实际帧率保证。

轻量惯性在手机 `inertia.js` 计算：取最近位移样本估计松手速度，超过阈值才指数衰减续滑；最大时长 600ms。新触摸、双指手势、页面隐藏或断线会停止续发，卡帧时终止以避免跳跃。原生输入已触发的浏览器平滑滚动可能短暂收尾，不能同步撤回已发送的滚轮。它仍发送普通 `control/scroll`，不增加协议动作。

服务、网页、插件统一版本，由 `scripts/bump-version.mjs` 管理；API 与 UI 均可查看。每次交付递增一次。

唯一落盘数据是粗略页面访问序号 `DATA_DIR/visits.json`。`POST /api/visits` 串行递增、原子替换文件，不保存访客身份。网页每次加载调用一次；资源请求与心跳不计数。文件损坏不静默归零，计数失败不阻塞控制。会话仍在内存，计数持久化不代表会话可跨服务重启。

连接码五分钟有效；待确认请求最多等待一分钟。旧码刷新后作废；配对后的码不能再使用。一个服务进程最多 100 个会话、200 条 WebSocket 连接，消息大小最多 4 KB，每连接每秒最多 180 条消息。

## 扩展权限

- `storage`：本地仅保存显式调试地址 `serverUrlOverride`，不再持久化默认地址；session storage 保存同服务后台重启需要的临时状态和令牌。切换服务清除旧令牌，避免跨来源复用。
- `debugger`：发送页面中心的原生鼠标滚轮，响应 Canvas 自定义处理器；仅批准后的滚动按需附着，正常结束或切换目标时释放。此权限较敏感，会出现浏览器提示，不再使用 `scripting` 或内容脚本。
- `alarms`：后台恢复检查。
- `<all_urls>`：支持用户主动切换的任意普通网页。只有 `activeTab` 权限不能持续控制后续切换的标签页。

手机令牌只保存在手机当前标签页的 `sessionStorage`；host token 在扩展的 `chrome.storage.session`，不发送给弹窗或被控制网页。调试读取仅用于视口尺寸，不向服务器传输网页内容。

## 安全与生产边界

- 配对需要电脑确认；四位码不视为授权凭据。猜码按直接连接 IP 每分钟五次限流。
- WebSocket 校验请求 Host 和浏览器 Origin，阻止普通外部网页连接本地服务。当前不设置 `EXTENSION_IDS`，允许不同电脑的扩展来源，无需登记 ID。代码保留可选限制能力，但本阶段不启用；未设置或空列表均表示不限制具体扩展 ID。
- 无 Origin 的原生客户端仍能连接，Origin 不是身份认证。当前没有账户认证、持久化审计、跨 IP 全局防爆破或完整抗 DoS 能力。
- 服务端只接受有限协议和数字范围，未配对连接、待确认手机不能转发控制，也不能执行 host 管理操作。
- 本地不传输页面内容，只转发指令。线上必须使用 HTTPS/WSS；TLS、反向代理、访问限制需由部署环境提供。
- 会话在内存中，仅支持单实例。多实例部署需要共享会话状态和消息转发，不能直接无状态横向扩容。
